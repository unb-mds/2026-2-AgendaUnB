## Anotações

- Planejamento da **Sprint 02**, estruturando os quatro artefatos centrais de definição de produto:
  - **Product Canvas:** alinhamento da proposta de valor, personas, jornadas principais e requisitos macro;
  - **Protótipo:** validação visual de fluxos (baixa e alta fidelidade no Figma) antes de codificar;
  - **Documento de Divisão / Fatiamento:** quebra do escopo em épicos, funcionalidades (*features*), histórias de usuário e critérios de aceite;
  - **Backlog do Produto:** lista priorizada de execução, associada no GitHub a *issues*, *milestones*, *specs* e *skills*.
- Foram debatidas as regras de acesso e permissões para criação de eventos públicos, comparando a restrição de postagem direta a contas autorizadas/institucionais com o uso de IA para triagem de conteúdo no contexto da UnB.
- Definiu-se o fluxo de versionamento com branches e Pull Requests no repositório: `branch` → `dev` → `testes` → `main`.
- A cadência semanal de planejamento foi ajustada para as terças-feiras, mantendo o domingo para revisão das entregas da semana.

## Ações necessárias

- Executar limpeza e padronização inicial do repositório (placeholders e `.gitignore`).
- Adotar o template oficial de MDS no Figma e estruturar os documentos de Visão e Requisitos.
- Configurar as primeiras *issues* e *milestones* no GitHub e iniciar a implementação do protótipo do front-end.
